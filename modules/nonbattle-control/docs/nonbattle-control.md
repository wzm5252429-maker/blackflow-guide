# 黑流树海非战斗接管

本模块取消截图管线的 16:9 前置限制，并将原始游戏截图、MAA OCR/模板/CorridorNet、当前冻结神经网络和 Windows 点击控制接入网站「路线决策」。用户点击「一键启动自动执行」后启用非战斗输入；启动本机服务、打开网页和单独配对不会开始接管。

目标固定为一结局。「开始战斗」「开始行动」和战斗画面不执行输入；用户手动作战后，循环继续读取战后画面。每次只执行一个同帧真实候选动作，然后重新截图确认结果。未知页面、资源缺失、目标变化或模型不匹配会等待，不补写模拟状态。

## 使用

1. 使用 Windows 10/11 x64、Python 3.13，并保留现有 BFMapRecognizer / MAA 运行资源。
2. 安装依赖：`py -3.13 -m pip install -r requirements-live.txt`。
3. 运行 `tools/Start-BlackflowLive.cmd`。它只启动本机服务并打开网站，不点击游戏。
4. 默认运行资源目录为 `D:/ArknightsAuto/BFMapRecognizer_v1.0.2_Windows/BFMapRecognizer`。其他位置使用 `py -3.13 -m blackflow_live --runtime "你的资源目录" --open-site`，或环境变量 `BLACKFLOW_MAA_RUNTIME`。
5. 如果只需连接本机，在路线决策页展开「首次使用 / 连接帮助」，点击「连接本机」。单独打开网站时，使用启动器显示的六位一次性连接码；从启动器打开时可自动配对。此步骤只连接和检测游戏窗口，不启动截图或点击。浏览器的本机网络访问权限由用户选择。
6. 准备启用非战斗操作时，点击「一键启动自动执行」。尚未连接时，按页面提示先完成配对。游戏画面和识别结果会在启动后显示；「开始战斗」及战斗过程仍由用户操作。
7. 暂停可用网站按钮、Esc 或桌面左上角；停止后必须重新启动会话。窗口切换导致点击目标被遮挡时停止输入。保持发起执行的控制页打开；该页心跳中断超过 20 秒后暂停，其他旁观页面的轮询不会延长执行时间。

网站通过 `http://127.0.0.1:19761` 与本机通信；截图和网络权重在本机处理，不发送到云端决策服务。公开网站本身不能启动 Windows 应用，因此使用时需要本机接管器保持运行。服务只允许明确的网站来源，并要求配对后的 Bearer 凭证；不开放任意坐标点击接口。

### 控制页、旁观页与暂停

启动会话的页面拥有本次执行的心跳。其他已连接页面可以查看状态和已有截图，也可以暂停或停止执行，但不会替控制页续租。关闭、刷新控制页或中断其与本机服务的连接后，即使其他网站标签仍然打开，执行也会在心跳中断超过 20 秒后暂停。

暂停会清除控制页归属。用户在任意已连接页面显式点击「继续」后，该页成为新的控制页；运行中的会话不能通过「继续」转移或保活。停止后的会话需要重新点击「一键启动自动执行」。

点击提交后若迟迟未确认界面变化，会自动暂停，避免反复提交同一动作。确认游戏可操作后，显式点击「继续自动执行」会重新聚焦、重新截图和决策，并在另一张新截图上核对目标后允许一次重试；仍无变化则再次暂停，不会无限重试。暂停前尚未完成的识别或推理会失效，快速暂停、继续也不能使用此前的工作提交输入。

本机服务使用 `page-owner-v1` 协议，健康接口版本为 `2`。旧网页缺少页面标识时不能启动或继续执行；新网页连接旧服务时需要先重启更新后的本机接管器。页面标识仅用于区分标签，接口仍要求原有配对凭证与来源校验。

### 已连接，但提示找不到游戏窗口

先确认真正的游戏画面已打开，而不是只有启动器。网站空闲时每 5 秒重新检测窗口，也可以点击「重新检测窗口」；游戏重启后会清除旧窗口选择。检测仅读取 Windows 窗口信息，不启动截图或点击。

连接模块根据 `Arknights.exe` 进程和 Unity 游戏窗口类型确认目标，不依赖标题必须完全一致。最小化、隐藏和不存在会分别提示；不会把浏览器中提到游戏的网页当作游戏窗口。「连接本机」仅检测窗口状态；用户点击「一键启动自动执行」后，控制会话才会尝试恢复最小化的游戏窗口。

更新本机模块后，需要关闭旧的接管器命令行窗口，再运行 `tools/Start-BlackflowLive.cmd`，从新打开的网页重新连接。已运行的 Python 服务不会自动加载刚更新的代码。需要先确认连接状态时，使用「首次使用 / 连接帮助」中的「连接本机」；准备执行时再点击「一键启动自动执行」。

## 分辨率和坐标

`capture.py` 直接使用 MAA FramePool 的原始客户区截图，绕过 MaaCore 的 16:9 截图代理；`geometry.py` 保留完整宽高比，仅移除成对均匀黑边。识别输入按高度缩放，宽度随实际画面变化。模板全图多尺度搜索，点击通过同帧逆变换返回实际客户区和桌面物理像素。每帧及输入提交前检查窗口句柄、进程、尺寸、位置和 DPI。窗口最小化、截图与客户区尺寸不一致时不猜测坐标。

原始 MAA ControlUnit / OpenCV x64 ABI 针对现有 `v6.17.0-beta.6` 资源。更换 MAA 大版本应重新验证 ABI；不能把无关版本 OpenCV DLL 混入现有目录。DLL、MAA OCR、模板和 CorridorNet 不随连接模块再分发，使用本机原有资源及其许可证。

## 实际验证与边界

- 已完成窗口全屏、2878×1659 客户区、200% DPI 的真实截图识别；保存画面生命 4/4、行动力 6、源石锭 25、当前希望 0、零件 2、藏品 1 已从像素回放核对。2026-09-20 更正：此前报告的希望 6 是灰色上限，旧版错误读了这个字段；新版定位随进度条移动的黄色当前数值。用户再次授权非战斗实机验证后，尝试点击相邻节点，但尚未确认游戏接受该输入；未开始战斗。
- 保存的历史地图回放曾读出 11 节点、11 道路、当前节点和第一层，与既有 MAA 图结构输出一致；资源值另按原图人工复核，以本次希望字段更正为准。识别过程只读截图，没有把旧 JSON 当作识别结果。
- 网络检查点使用当前选择 `opportunity_weighted_002` 的真实路线与菜单权重，按 SHA-256 和特征签名校验；不回退到随机动作或人工路线评分。
- 回放与模拟输入测试覆盖宽高比、黑边、DPI、陈旧截图、重复点击、目标变更、战斗屏蔽、两帧结局确认、暂停/停止竞争、断连以及本机接口认证。
- **尚未达到“除战斗外所有页面均可无人干预直到一结局”的完整实机验收。** 商店、招募、事件、库存及移动确认已有截图候选处理，但真实页面覆盖、滚动/完整背包扫描和通用干员身份特征仍有缺口；遇到未覆盖情形会明确等待。
- 没有训练新网络，也没有证明模拟环境的成绩可迁移成真实通关率。一结局仅在同帧结算界面出现明确一结局身份、并经独立第二帧确认后标记完成；模糊通关文字不会冒充一结局完成。

详细策略特征覆盖见 `docs/live-policy-coverage.md`；视觉能力以当前检测器和截图回放为准。此版本是可运行、可扩展、具有明确暂停边界的接管实现，不能把尚未覆盖的游戏分支描述为已经完成全自动通关。

## 开发与验证

2026-09-20 更新：初始招募页可从同列完整标题识别三张职业招募券，应急招募页可识别干员预览与离开。弱文字或叠影仍按招募覆盖层处理，不能点击背后的地图。实际招募要求同帧完整身份、选中状态、可用按钮、明确费用及余额；目前详情页视觉尚未提供完整证据，因此不会仅凭“雇佣”二字确认招募。此更新已用保存录像像素回放，不代表当前游戏完成了招募。

原网络对先锋、辅助、特种券的现有特征相同，三者回放概率均为 1/3；不能将这一选择描述为学会了职业偏好。

后续 v9 更新已补初始招募完成页的入场按钮、助战详情的可靠返回，以及普通列表中的干员预览和明确零费确认。原录像地灵页面具备合法确认，但当前网络在同时存在梓兰预览时选择了梓兰；这是合法换卡，尚不能证明最终确认或连续闭环。付费招募页的希望条会在选择时变化，目前尚未证实其余额语义，不回算余额。助战确认、付费确认和连续招募仍需补齐。未改变网络权重或隐藏真实候选来制造通过结果。

运行 `py -3.13 -m unittest discover -s tests -p "test_live_*.py" -v`。这些测试不向真实游戏提交输入；真实模型测试只执行本机神经网络前向计算。部署包可用 `py -3.13 scripts/package_live_connector.py --output <目录>` 生成，包含冻结推理依赖和所选权重，避免覆盖研究工程正在进行的训练修改。

浏览器连接依据：[Chrome 本机网络访问说明](https://developer.chrome.com/blog/local-network-access?hl=zh-cn)。物理 DPI 坐标依据：[Microsoft DPI awareness](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setthreaddpiawarenesscontext)。MAA 资源与算法来源：[MaaAssistantArknights](https://github.com/MaaAssistantArknights/MaaAssistantArknights)。
