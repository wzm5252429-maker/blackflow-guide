# 实机画面识别实现与离线验收

`blackflow_live/vision.py` 直接运行已安装 MAA 包的 PaddleOCR 检测/识别模型、黑流地图模板和 CorridorNet。输入只有当前提供的 BGR 截图，输出坐标属于同一张识别图；窗口位置、黑边和屏幕坐标的逆变换由 `geometry.py` 负责。识别模块不连接鼠标键盘，也不运行原 `MapRecognizer.ps1` 的任务链。

当前地图路径是：全图 OCR → 节点名称/空地/当前位置模板 → 从实际节点位置聚类行列 → 对实际相邻节点截取道路图块 → CorridorNet 判边。不会读取旧 `map_result.json`，不会补入模拟器默认生命、行动力、希望或背包。小节点的类型、隐藏状态和资源均保留截图能证明的范围。

HUD 识别使用“目标生命值、行动力、零件箱、收藏品”的实际文本位置作为锚点；希望和源石锭使用两个小图标模板。模板遍历实际截图并搜索多个比例，数值区域相对于识别到的图标或文字定位。模板来源及源图摘要记录在 `blackflow_live/assets/hud_icons.json`。识别失败时资源字段缺失，路线策略会等待重新观测。

目前非战斗画面支持事件选项、商店、招募、奖励、背包以及地图移动预览的候选动作。事件标题与已固定的客户端选择表精确匹配；物品、干员名与本地目录精确匹配。购买价格仅来自按钮附近明确写出的售价/价格/消耗文本，条件未满足的选项会禁用。物品与干员列表候选先表示打开详情的预览，不伪造价格、库存、干员能力或真实背包完整性。

“开始行动/开始战斗”等文本和战斗模板优先于其它场景，识别到后输出零个可点击动作。普通通关图标不等于一结局；必须同时有高置信的结算画面证据以及“结局一”或客户端 `ro6_ending_1` 的名称“强制重启”，才输出 `ending_complete`。控制循环还需第二张截图再次确认。

## 已执行的验证

- `py -3.13 -m unittest tests.test_live_vision -v`：19 项合成/离线测试，覆盖未知画面、战斗边界、结局确认、截图坐标、资源漏识别、禁用选项、价格来源、实际模板匹配和道路 RGB 预处理。
- 已保存的 2026-08-29 地图原图回放：11 个节点、11 条无向道路、当前位置 `r1c1`、第 1 层；识别到生命 `4/4`、行动力 `6`、零件 `3`、收藏品 `1`、希望 `5`、源石锭 `25`。运行中未读取该历史图的 JSON 结果，图结构数量与旧 MAA 输出一致。
- 已保存的窗口全屏设置画面回放：OCR 读到“设置、分辨率设置、窗口全屏”，场景保持未知，候选动作数量为零。
- 回放的完整 OCR、坐标和耗时在本地 `artifacts/live-vision-replay/`。两张图上的 CPU 感知约为 13 秒和 8 秒，随机器负载变化。

2026-09-15 用户重新授权非战斗实机验证后，已补充窗口全屏、200% DPI 的三帧真实截图。2026-09-20 独立复核发现此前“希望 6 已正确读取”的结论错误：黄色当前数值为 0，灰色 6 为上限。新版已修正定位并更正两份 fixture 的人工期望；生命 4/4、行动力 6、零件 2、收藏品 1、源石锭 25 不变。原三帧模型曾选择相邻作战节点预览，但其希望输入错误，该记录不能作为策略资源输入全部正确的证据。Computer Use 的两次节点点击未确认产生界面变化，尚未证明实际输入生效，没有开始战斗。

地图希望数字随填充条移动，当前实现以希望图标定位区域，仅提取完整黄色数字并用多种预处理一致复核；灰色上限不参与当前余额识别。空白或冲突保持未知。真实录像中的 6/6 和 0/6、保存的两份窗口全屏 HUD 与一帧原生地图已分别验证；移除黄色当前数值仍保留灰色上限时不会补出希望。

生命值优先保留与文字锚点关联的完整分数，必要时在同帧数字框内复核；藏品数量通过前景隔离复核。冲突、空白、遮挡或低置信结果仍保持缺失。两个 HUD 实际像素回归样本随包提供，仅含用于验证的游戏 HUD，不是完整策略输入图。

2026-09-15 后续回归加入已有录像的非战斗画面：地图节点“出发前往”预览、两张奖励卡片、交易弹层。奖励的“收下”只关联同列、同卡片的唯一高置信物品标题；领取按钮已经出现时移除该卡片重复的标题预览候选。未读清的卡片身份保持未知，不提前计入库存。

交易弹层通过同一底栏的“确认购买/确认出售”和“算了”识别遮挡；即使问句缺失、低置信或过渡叠影使交易类型不明确，也不能让背景地图和货架重新成为可点击候选。实际确认交易还要求上方完整交易问句。低置信确认文字仅在原按钮框扩边后以两种灰度处理复核，不能降低全局文字阈值。物品标题与问句内名称必须一致，价格来自完整问句重读；购买另需当帧源石锭足够。取消弹层不等于离开节点。真实录像中“浪花”的出售确认读到18源石锭；购买过渡叠影图仅提供已核实的“算了”，没有补造价格。样本出处、帧时间及摘要在 `tests/fixtures/live_rewards/manifest.json` 和 `tests/fixtures/live_shop_dialog/manifest.json`。

## 尚未证明的覆盖范围

2026-09-20 招募回放：两张原录像帧加入 `tests/fixtures/live_recruitment/`，来源、时间及哈希见 manifest。初始页以完整“初始招募”标题、同列职业券全名和“招募”按钮定位预览；低置信券名需局部两种处理一致复核，不补齐残缺前缀。应急页通过同排雇佣/离开底栏隔离背景，精确匹配帕拉斯、Pith 等候选；客户端干员目录补充了 MAA 词表没有的集成战略专属干员，冲突身份直接删除。弱底栏仅允许充分卡片证据支持的预览，不能成为雇佣确认。此次未生成实际雇佣动作。

后续 v9 已补初始完成页：完整入场文字与相邻 MAA 专用鹿标记共同证明目标，文字较弱时同框彩色/灰度重读须一致；残留招募券、重复按钮或错位标记仍等待。助战详情以完整“招募助战”局部双读及左上 Return 模板提供返回，不补造干员身份，不确认助战。

普通招募列表以实际暗色卡片轮廓定位名字与费用区域，完整标题带局部双读可补全图 OCR 漏检，但不会按残缺前缀补名字。最终零费确认要求左侧完整身份与唯一高亮同名卡一致、希望费用图标及数字 0、完整当前零值单元和启用按钮共同出现。费用数字、当前零值模板与来源均随 `live_recruitment_cards` fixture 记录。付费选择后希望条发生动画变化，暂不将其当作招募前余额。

后续连续录像发现：鼠标遮挡确认文字时，即便完整招募模板也可能失效，而通用小勾号仍匹配。该小图案现只作为 `confirmation_icon` 诊断，不能独立证明结算场景，也不贡献一结局确认；明确结果文字或 GamePass 大标志仍与一结局身份联合判断。移除误判不等于恢复被鼠标遮挡的招募文字，这些帧仍可能没有可执行动作。

点击后若新截图仍在原游戏窗口、用户未移动或按下鼠标，执行器可延后将指针移至可见游戏客户区角落，再取新图识别。该移动与点击分批，不包含按钮输入，不作为点击已生效的证明；若网络仍选上一次同目标，会暂停而不重复点击。暂停、停止、重新聚焦、战斗和结局都会丢弃待执行移动。识别预览不移动指针；unknown/loading 可以执行上述一次受约束的移动以消除遮挡，但不会因此允许普通点击。此项已通过离线输入模拟，尚未实机验证遮挡改善。

招募图标匹配在 OCR 字框估计尺度附近 ±8% 搜索最佳图像匹配，保持原置信阈值，避免 23/24 像素字框抖动使全部图标及当前希望定位失败。费用至少需两次高置信数字一致，并拒绝其它可信数字冲突；单次把选中卡的零读成 3 不再进入观测。原录像 10.4 秒已作为新增像素样本，但完整卡名及费用仍不足以确认该次招募。

保存画面地灵的合法确认与梓兰预览同时存在时，当前网络选择梓兰；这是另选候选，并非已经确认招募。完成页入场和助战返回已由当前网络选出，所有证据仍为离线回放，不能当成当前游戏连续流程验收。

目前只有少量奖励、交易和移动预览录像回放，尚无事件、商店、招募、背包和实际结局的完整实机连续流程；不能把候选动作的实现和截图测试等同于已跑通所有游戏菜单或一整局。列表滚动、跨页背包盘点、无文字图标按钮、灰色锁定状态、未收录干员、特殊事件多步骤页面，以及不同 UI 缩放后的 HUD 数字精度，需要后续保存画面补充回归。当前实现不会因为这些缺口自行猜坐标或补状态；它会暂停在没有可证明动作或必要资源缺失的位置。

任意宽高输入已经支持，截图和点击坐标不再依赖 16:9。原生超宽屏实际重新排列后的完整菜单识别率仍需实机画面验证；分辨率变换测试不能代替这种内容验证。
