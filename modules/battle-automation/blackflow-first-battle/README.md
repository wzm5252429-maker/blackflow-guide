# 黑流树海第一场战斗闭环 Agent

这是一个运行在 **Windows 明日方舟 PC 客户端**上的第一场战斗闭环工程。它把 MAA 式的视觉识别与确定性动作执行，和一个持久化 Q-learning 策略选择器组合起来：第一局按你写的合法战术打；识别胜利、失败或超时后更新该战术的价值；以后逐渐偏向胜率更高的战术。

它不是一个已经掌握未知关卡的成品模型。真实通关前必须把你这次第一层第一场作战的三个结果模板、部署坐标和干员顺序填进去。程序框架、实时闭环、动作验证、日志和学习器已经完整；缺少的是只有你当前游戏画面和具体打法才能提供的数据。

## 一、闭环如何工作

每一局都执行以下过程：

1. 找到标题包含“明日方舟”或“Arknights”的窗口并置于前台。
2. 点击“开始行动”，持续截图，直到识别到战斗界面。
3. 根据当前上下文，从 `plans` 中选出一个战术。
4. 等待每个动作的画面条件或战斗时间条件，执行点击、拖动部署、技能或撤退。
5. 每次动作后可用 `verify` 条件确认成功；失败时重试或保存截图并停止。
6. 全程识别胜利、失败和超时。
7. 将 `(局面, 战术, 奖励)` 写入 `learning/q_table.json`，下次启动继续学习。
8. 将完整事件记录和关键截图写入 `logs/`。

急停键是 **Ctrl+Alt+F12**。`pyautogui` 的安全保护也已开启：把鼠标快速移到屏幕左上角会立即中断。

## 二、第一次运行

1. 解压整个文件夹，不要只取出某一个 `.py` 文件。
2. 双击 `01_install.bat`。它使用你电脑可用的 `py -m pip` 安装依赖，并自动生成可编辑的 `configs/strategy_first_battle.json`。
3. 双击 `02_run_simulation.bat`。这不会点击游戏，会运行 80 局虚拟战斗，检查学习器能否逐渐偏向高胜率战术。
4. 将明日方舟 PC 客户端设为 1920×1080，并保持前台可见。程序可以按比例适配其他窗口大小，但首次标定建议使用 1920×1080。

## 三、采集三个必需模板

模板匹配比整屏 OCR 更稳定。至少需要六张很小的图：

- `battle_started`：战斗中稳定出现的 UI，例如右上角速度按钮的一部分。
- `victory`：胜利结算中独有且稳定的字样或图标。
- `defeat`：失败结算中独有且稳定的字样或图标。
- `card_blocker`：你策略里的地面阻挡干员处于“费用足够、可以部署”时的卡片特征。
- `card_healer`：治疗干员可部署时的卡片特征。
- `card_damage`：输出干员可部署时的卡片特征。

操作方法：

1. 进入相应界面，双击 `03_capture_window.bat`，截图会保存为 `calibration/window.png`。
2. 双击 `03b_crop_template.bat`，输入上面的英文名称，用鼠标框选一个小而独特的区域后按 Enter。
3. 工具会保存 PNG，并自动更新 `configs/strategy_first_battle.json` 中的模板路径和 ROI。
4. 对六个检测对象分别完成一次。胜负界面无法同时出现，可以分别截图、分别框选。干员卡模板建议只框头像内部独特区域，不要包含会变化的费用数字。

框选原则：区域尽量小，只包含不会随干员、数值和动画变化的内容。不要把半张画面都截进去。

## 四、把你的打法写入策略

主要编辑文件：`configs/strategy_first_battle.json`。

### 4.1 坐标

`points` 保存 1920×1080 基准坐标：

```json
"points": {
  "card_1": [1370, 1000],
  "main_block_tile": [980, 650],
  "skill_button": [1665, 775]
}
```

要查看某个位置的坐标，先截取窗口，再双击 `03c_get_point.bat`，在图片上框一个很小的区域。窗口会输出中心点坐标。

### 4.2 部署动作

```json
{
  "label": "部署地面阻挡",
  "type": "deploy",
  "card": {"detector": "card_blocker"},
  "tile": {"point": "main_block_tile"},
  "direction": "left",
  "when": {
    "all": [
      {"elapsed_ge": 4.0},
      {"detector": "card_blocker"}
    ]
  },
  "timeout": 20,
  "retries": 1
}
```

`direction` 可填 `left`、`right`、`up`、`down`、`none`。

### 4.3 开技能

```json
{
  "label": "开启主力技能",
  "type": "skill",
  "operator": {"point": "main_block_tile"},
  "skill_button": {"point": "skill_button"},
  "when": {"elapsed_ge": 28.0},
  "timeout": 40
}
```

### 4.4 用画面而不是时间触发

用标定工具额外创建例如 `main_skill_ready` 模板后，可以写：

```json
"when": {"detector": "main_skill_ready"}
```

也支持组合条件：

```json
"when": {
  "all": [
    {"elapsed_ge": 20},
    {"detector": "main_skill_ready"}
  ]
}
```

### 4.5 动作后验证

因为示例用干员卡模板动态寻找卡片，即使部署后其他卡片横向移动也不会丢失坐标。部署动作可以同时用同一模板确认卡片已经离开待部署区：

```json
"verify": {"detector": "card_blocker", "matched": false},
"verify_timeout": 3,
"retries": 1
```

这会在拖动失败时自动重试，而不是假定部署成功。

## 五、强化学习到底学什么

`plans` 中的每一项是一套你允许程序尝试的完整战术。示例提供三套不同部署顺序。学习器不会创造非法点击，而是在这些安全战术之间探索。

更新公式是：

```text
Q(战术) ← Q(战术) + α × [奖励 − Q(战术)]
```

默认奖励：

- 胜利：`+1.0`
- 失败：`-1.0`
- 超时：`-1.2`

`epsilon` 控制探索概率，并会随对局逐渐下降。每套新战术至少尝试一次，之后通常选择当前 Q 值最高的战术，同时保留少量探索。

第一场作战在同一次肉鸽探索里不能原地重打，所以学习主要跨不同肉鸽局保存。单局运行用 `04_run_first_battle.bat`；下一次回到同样的第一场战斗时再次运行，它会读取之前的 Q 表继续学习。

只有在你已经把“胜利后回到新一局第一场战斗”和“失败后重开”的完整点击过程写进 `reset_after_victory`、`reset_after_defeat` 后，才能安全使用 `05_train_repeatedly.bat`。默认留空，因此程序不会擅自乱点下一局。

## 六、真实运行前检查

- 游戏窗口必须可见、不能锁屏，也不要让其他窗口遮挡。
- 三个模板文件均已生成。
- `start_battle_button`、待部署区卡片和地图格坐标已按你的画面标定。
- 三套 `plans` 已改成真实干员顺序；如果阵容固定，只保留一套也能执行，但只有多套战术时才有可学习的选择。
- 先在低风险环境运行一局，并随时准备按 Ctrl+Alt+F12。

完成后，停留在可点击“开始行动”的界面，双击 `04_run_first_battle.bat`。

## 七、输出文件

- `learning/q_table.json`：真实对局学到的 Q 值、访问次数和胜率，永久保留；删除它等于清空学习。
- `learning/simulation_q_table.json`：仅供模拟测试使用，不影响真实游戏。
- `logs/日期时间/events.jsonl`：每个动作、结果和错误的结构化记录。
- `logs/日期时间/*.png`：胜负、超时或动作失败时的截图。

## 八、当前边界

这个版本能够完成“你提供策略 → 动态识别 → 实时执行 → 验证 → 判断胜负 → 强化更新 → 下局复用”的完整闭环，但不会凭空推导一张未知地图的最优打法。第一场能否实际通过，取决于你提供的打法、阵容、地图坐标和模板是否正确。后续可以在这个接口上继续增加费用 OCR、干员头像识别、血量/蓝门压力识别，以及针对单步动作的更细粒度强化学习。
